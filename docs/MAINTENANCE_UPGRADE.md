# 0.6.0 信任配置与关系维护升级

升级前停用插件，备份旧代码、AstrBot 插件配置及整个 `data/plugin_data/astrbot_plugin_bond/` 数据目录。复制 SQLite 文件前先停止写入，在线备份使用插件提供的备份功能。

## 首次升级会覆盖哪些设置

首次加载 0.6.0 时，以下五项 T 专属配置统一设为新值。旧版自定义值同样会被覆盖。

| 配置 | 新值 |
| --- | --- |
| `relation_daily_caps.trust_up` | `2`，基础每日正向额度 |
| `relation_daily_caps.trust_down` | `8`，每日负向额度 |
| `decay.trust_enabled` | `true` |
| `decay.trust_half_life` | `60` 天 |
| `decay.trust_baseline` | `20` |

共享的 `decay.grace_days`、`decay.maintenance_strategy`、`relation_mode`、F/A 配置与各 Provider 选择均沿用保存值。Galgame 将正向请求与正向额度乘 2，因此默认 T 每日上限为 +4/−8。

覆盖前的五项设置保存到数据目录下的 `trust-settings-before-0.6.json`。文件已存在时保留原文件，内容仅含将被覆盖的信任字段。内部标记 `trust_config_version` 随配置一起保存，用于识别升级已完成。升级成功后，用户再次修改的 T 设置会在后续重载时保留。该标记由插件管理。

若升级后的配置保存失败，插件撤回本次内存修改并报错。处理配置文件权限或存储故障后再重载。回滚所需的完整配置、数据库与旧代码仍须按上方方法成套备份。

## 为什么显示的信任度可能立即变化

本次信任配置迁移保留数据库中的原始 T、既有时间锚、维护时间和历史流水。重载后从原锚点直接使用新衰减参数计算当前有效值，省去按旧规则结算或过渡双算法。因此显示值可能立即变化，尤其是原先关闭衰减、采用其他半衰期或基线的安装。

默认信任半衰期为 60 天，对称基线为 20。超过既有保温期后，+40 经过一个半衰期约为 +30，−40 约为 −30。−20～+20 内的值保持原值。共享保温期沿用原配置，时间淡化也不会重放历史奖励。

本次数据库升级至 **schema 19**。相对 schema 18，仅新增 `relation_title_cache` 与 `relation_title_calls`，分别保存可重建的称谓缓存与独立调用预算。更早版本会依次执行既有迁移，schema 18 引入的三维维护时间与亲近托底参考继续使用。

## 哪些互动会维护关系

默认策略为 `independent`，分别判断各维维护资格。普通问答维护 F，亲近事件维护 A，只有通过证据校验的合格信任事件维护 T。感谢、示好、道歉、普通 `insult` 和 `manipulation` 的 T 为 0。

资格依据接纳事件的原始非零维度请求、倍率与规则、剩余每日额度判定，再应用精度与分值边界。合法变化因精度归零或数值封顶仍可维护，规则归零、额度耗尽、失败、弃权、重复事件和冷却均无法取得独立维护资格。

`legacy` 让已接纳事件联动维护 F/A，T 仍只接受自身的合格信任事件。手动切换维护策略时，各库沿用既有事务结算机制，保存策略及生效时点，失败回滚该库切换。该操作与本次 T 配置一次性迁移分别执行。

成员详情与列表的最近互动取三个维度最近的真实维护时间。读取、策略切换与衰减结算均不产生新的维护时间。临时关系暂停正式衰减，结束后只补回一次暂停时长。

## 回滚

停止插件后，成套恢复升级前匹配的旧代码、AstrBot 插件配置与完整数据目录。仅切回 `legacy` 属于维护策略调整，回滚版本仍须恢复成套备份。旧代码会拒绝高于自身支持版本的数据库，修改版本号或 `PRAGMA user_version` 无法完成回滚。恢复旧备份后，备份时点之后的改动会丢失。

## 诊断与验证边界

关系诊断默认关闭。启用后可查看三维请求、规则后与额度后增量、维护资格、实际维护与原因。`rule_zero` 表示规则归零，`quota` 表示额度耗尽，`precision` 表示精度归零，`bound` 表示分值封顶。

0.6.0 的可信事件和称谓规则见 [评估框架](ASSESSMENT_FRAMEWORK.md)。本说明依据当前实现整理，真实 QQ、真实模型表达和线上升级效果仍需维护者验收。
