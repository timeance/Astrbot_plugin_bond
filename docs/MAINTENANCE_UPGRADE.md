# 0.4.5 关系维护升级

默认 `decay.maintenance_strategy=independent`。普通问答维护熟悉度，亲近与信任只由各自合格事件维护。资格按原始增量、倍率/规则和可用额度判定，再执行分值精度与边界限制；精度归零或数值封顶可以维护，规则归零、额度耗尽、未接纳、去重和冷却不会维护。

## 升级与回退

1. 停止或卸载插件前，备份完整插件数据目录（含所有 Bot/空间数据库和配置）。使用插件原有备份入口也须分别保留需回退的数据库。
2. 安装本版本并重载。既有数据库升级到 schema18，继承旧维护时间，按旧语义结算至切换时点；分值、流水、额度和资料保留，不从升级时重新发放保温期。
3. 若只想恢复统一保温，在关系变化中选择 `legacy` 并重载。每次切换仅结算一次；未再次发言的成员同样在重载时切换。
4. 若要退回 0.4.4 代码，先停止插件并恢复升级前的完整数据备份。旧代码拒绝 schema18；仅降低版本号或修改 `PRAGMA user_version` 不能安全回退。回退会丢失备份之后的改动。

## 时间与诊断

成员详情与列表的最近互动取三个维度最近的真实维护时间。读取、策略切换和衰减结算不算互动；临时覆盖暂停正式衰减，结束后只补回一次暂停时长。

默认关闭的关系诊断新增三维原始/规则后/额度后增量、维护资格、实际维护、原因、维护前后时间及策略生效时间，均来自提交关系变化的同一事务，不增加聊天原文采集。`rule_zero` 表示倍率或事件规则归零，`precision` 表示合法变化因一位小数计分归零，`bound` 表示触及分值边界。

此阶段只导入维护功能；回复行为、消息快照和详细诊断采集在后续独立 PR 审核。真实 QQ 与真实模型行为需由维护者在合并后验证。
