# 关系评估框架（含 0.5.0 更新）

模型负责语义，框架负责可信来源和可审计的数值约束。本版本不新增底层关系维度、自动信任修复事件或第三方群聊监控，不改变人格、权限与接话策略。

## 0.5.0 维护与单轮资料合同

新策略 `decay.maintenance_strategy=independent` 默认开启。资格按接纳事件的原始非零维度请求、现有倍率/规则与剩余每日额度判断，在精度归零前判定，再单独应用总值边界：达到数值上限可继续维护，额度耗尽或规则归零不能维护。`should_update=false`、失败、弃权、冷却和重复消息不维护。普通问答只维护 F，友好与负面事件依既有映射维护对应维度；不增加新的信任修复。

Schema 18 将结算时间与合格维护时间分开，A 另保留托底参考。读取以“结算时间”和“最后维护时间加保温期”两者较晚者作为本段衰减起点；切换结算不产生互动，不刷新保温。F-only 写入不修改 A/T 的值、结算时间、合格维护时间、A 托底参考或半衰期。既有指数公式、默认参数与关系维度保持不变。

插件重载时为已有 Bot 的两个空间装配服务，不等到成员下一次出现才切换。各库在事务内统一结算全部成员并写入策略及生效时点；失败回滚整库切换，重启不重复结算已经成功的切换。`legacy` 恢复以后接纳事件统一维护的逻辑，不回滚历史分值。临时覆盖期间仍暂停正式时钟，策略切换不重复补回暂停时长。降级代码至旧 schema 与配置切换不是同一件事，降级须恢复匹配的备份。

标准群消息入口在调度该消息的后台评估之前，以同一 SQLite 短读事务取得档案、临时覆盖、证据及读取时间，再冻结本轮实际注入的完整文本，覆盖称谓/释义、印象与近期证据。相同事件重试和生成续轮复用，下一条独立消息刷新。快照绑定可信成员和原始空间，不因引用他人或后续切换空间而串档。捕获失败时本轮跳过注入，不在后台写入后补读；不会持有数据库锁等待 LLM，也不串行化所有群消息。资料固定包裹含可信 Bot、空间、群、成员与读取时间，证据包含发生时间，不改变自定义模板占位符。绕过标准入口的第三方/主动请求只能在首次请求钩子冻结，不能保证早于外部写入；缺少可信身份或 Bot 不匹配时跳过。

默认行为指导把正常求助、昵称、临时扮演、持续身份、排他要求与权限分开，并允许符合人格的熟悉与亲近表达。提示词不是权限控制。自定义模板保持原样；真实模型是否更自然、更有趣，另按 [行为验收](P0_BEHAVIOR_EVALUATION.md) 比较，不由工程测试推定。

## 参数与计算顺序

新安装 `relation_mode=galgame`；明确保存的 `realistic`（页面称“基础”）保持不变。`relation_daily_caps` 是基础正负额度：F 5/0、A 10/8、T 2/5。Galgame 只把正向请求和正向额度乘2。默认 insult 为 A−1/T−1.5，manipulation 为 A−0.5/T−2；感谢、示好、道歉的 T 为0。

计算顺序：受限事件基础增量及单事件基础限幅 → F 自身分段 / A 原有阶段与同日递减 → 正向模式倍率 → 相应单事件上限 → 最终 A/T 一位小数 → 独立每日方向额度 → 总值边界。负向不经过正向倍率；A 同日递减不影响 F/T。现有显式 Economy 参数与旧缺省预设继续作为基础参数，不被模式切换覆写。

F 六段边界为 `<10、<30、<55、<80、<95、其余`，倍率为1.5/1.2/.8/.5/.3/.15。已有 REAL 列保存至8位小数，公开显示一位小数，不新增奖励队列。每个已接受事件的原始 F 实际增量记在流水中，按同等精度占每日额度。重复ID、模型不应更新、错误输出不积累余量。人工设值明确替换当前F（包括余量）；撤销按实际向量反向，重做同理。到达100时多余奖励直接丢弃。

F/A阶段计算和A正向次数读取位于同一 `BEGIN IMMEDIATE` 事务，避免并发请求同时领取“首次互动”倍率。正负用量不抵消；撤销不退还互动额度、不回退同日次数、不退还模型调用预算。管理员设值不消耗互动额度；重置成员会清除该空间的状态与互动账本，但模型调用账本保留。

## 三维衰减

> 以下为0.3.8的参数与计算说明。0.4.2起，熟悉度默认半衰期为30天、基线10，信任度默认半衰期为60天、基线20；亲近度仍为30天、基线0。当前默认另含5天关系保温期，仅超过保温期的时间参与衰减。已有明确保存的设置不被覆盖。

F 默认启用、60天，无等级托底；A 默认启用、30天，保留原有等级托底与显式巩固设置；T 默认启用、90天，无等级托底。三个默认基线均为0，开关、半衰期和基线均可独立调整，两种模式参数相同。这些是产品参数，不是心理学标定结果。

基线是0～100的非负幅度。F在0～基线之间保持不变；A/T在−基线～+基线之间保持不变，范围外向同号基线收敛。不会把低于正基线的分数自动抬高，也不会把轻微负值压到负基线。半衰期减半的是“距离目标基线的差”：信任基线20时，+40在90天后约+30、180天后约+25；−40分别约−30、−25。

基线为0且没有互动时，F=40在60天后约20，A=40在30天后约20，T=±40在90天后约±20（A仍受显式托底设置约束）。自然衰减不占互动扣分额度，熟悉度的负向互动额度仍为0。

F/T使用独立 `familiarity_updated_at` / `trust_updated_at`，A沿用 `updated_at`。F/T未发生该维有效变化时保留其原值与时间锚，发生变化则先结算有效值再加事件增量；F以未舍入的有效值选择增长分段，保留原有8位存储精度。临时关系暂停三维正式时钟，到期只平移暂停时长。读取不写库；调整半衰期或基线并重载后，从原锚点用当前参数计算。F/T使用 `decay.familiarity_baseline` / `decay.trust_baseline`，A使用新键 `decay.affinity_baseline`；旧版已失效的 `decay.baseline` 从可编辑配置中移除，AstrBot加载时会清理该废弃键，防止升级时意外重新启用历史参数。撤销在当前有效值上反向实际事件增量，不重演全部历史，也不回滚衰减配置。

## 调用与上下文

`assessment` 默认窗口300秒/5次初评，用户每日初评30/复核8，Bot每日初评300/复核100，并发2。初评和复核分别记账；复核属于同一互动，不额外授予初评机会。调用发起前持久保留，失败/超时/进程中断的已保留尝试仍占次数；缺少Provider、本地拒绝或预算不足不记未发起调用。旧 `cooldown_sec` 留档，不再参与自动评估阻断。

UTC日期调用账本与配置时区关系额度分开；滚动窗口可跨UTC零点。插件共享预算锁合计同Bot的两个数据库，数据库事务再次检查本库；稳定事件ID在两个空间的调用记录中去重。重启不清零调用账本。主动恢复旧备份会恢复当时账本，不构成连续调用审计。本版本不承诺多个独立AstrBot进程同时挂载同一数据目录的跨进程分布式预算。

上下文仅包含可信同Bot、同群、同成员的近期相关互动和必要Bot回复，以及同群已计分摘要。默认6条、4000字符、7天/8条摘要；内存会话数和条数另有硬上限，重载后近期未持久化对话不可恢复，已计分证据仍可读取。原群筛选在SQL分页之前执行；旧global流水没有可靠来源群时不加入上下文。新流水仅新增原群字段，不建立全群第三方会话存储。

初评和复核共享一次冻结的上下文和提示词快照。`should_update=false`表示模型认为当前不应计分；解析兼容旧三字段响应，但旧响应不提供显式新颖性判断。事件类别、有限置信度和当前连续原文证据继续强校验。上下文和提示词不能保证模型完全正确，真实模型效果必须独立评估。

## Schema17升级与回退

- 各Bot的group/global库逐版本升级至17，DDL/DML和版本号在各版本的同一迁移事务中提交，失败回滚至该版本起点。
- Schema16新增每日六个方向累计、A正向次数和旧用量补齐标记、T独立时间锚、模型调用时间、流水原始群，以及窗口/事件/上下文查询索引。Schema17只新增F独立时间锚，不新增奖励队列或关系维度。
- 既有关系分值和历史奖励不翻倍、不重算。旧T从升级16、旧F从升级17的时刻开始计时，不对各自升级前的空闲时长追扣。跨升级的临时覆盖扣除已暂停时长，结束时不重复延后；已过期但尚未结算的覆盖同样处理。
- 旧每日净额先拆出能证明的方向用量；首次使用当天时按当前配置时区读取该日流水补齐正负总量（包括已撤销、曾实际消费的事件）。若历史日志缺失或曾使用其他时区，只能保留可证明用量下限，无法恢复丢失事实；不会伪造精确历史。次日新账本完整独立记账。
- 旧调用仍计UTC当日次数；无精确发起时间的旧调用不补造300秒窗口时间。
- 面板恢复沿用同schema备份校验，不直接导入旧版本备份；跨版本回退需恢复与备份匹配的代码和配置。
- 升级无需重置。升级前停写并备份代码、宿主插件配置和整个插件数据目录；回滚时恢复这三者。旧代码拒绝高于自身支持版本的schema17，不能只回退代码或手动降低PRAGMA。
