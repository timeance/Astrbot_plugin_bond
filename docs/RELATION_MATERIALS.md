# 关系资料与印象（0.7.1）

Bond 提供当前关系释义、可修正的成员印象和少量有效经历。关系计算、事件分类、评分、衰减、独立保温、额度、舍入和被动熟悉度规则均沿用 0.7.0。

## 使用

- 成员详情 →「当前关系资料预览」→「只读预览」。先选择 Bot、空间和真实群。只读当前状态，不生成回复、不调用模型、不刷新印象、不生成称谓、不结束临时关系、不提交衰减或推进评估进度。未加载空间显示缺少资料，不为预览初始化空间。全局关系仍不披露其他群的印象或经历。
- 设置 → 系统诊断 →「查看历史关系资料」。最多显示最近20条已保留的注入记录及程序筛选理由。历史正文来自当时保存的请求，不查当前关系回填。完整上下文记录遭脱敏、裁剪、容量淘汰或没有元信息时，明确显示无法还原或未记录。
- 历史记录表示 Bond 处理边界实际提供、观察到的内容，不保证是所有后续插件处理后的最终网络请求，也不是主回复模型的隐藏推理。
- 清除诊断会清除诊断文件、待写副本和页面已加载副本；不删除关系、评估流水或 AstrBot 历史。关闭/降低档位不会改写已保存历史。

## 四档与默认值

| 档位 | 保存内容 |
| --- | --- |
| 评估记录（assessment） | 结构化评估、关系变化和本轮选择/排除原因，不含资料正文 |
| 原文+评估（raw） | 再保存本次相关原文、可信引用与可取得的 Bot 回复；不保存完整关系块 |
| 评估上下文（evaluation） | 再保存评估模型实际输入、初评/复核输出；不额外保存主回复关系块 |
| 完整上下文（full） | 再保存 Bond 观察到的主回复请求；关系正文在该请求中定位，不另存一份 |

当前核实的 0.7.0 默认是第一档。本次按任务要求将缺省值改成第二档；已有显式 assessment/raw/evaluation/full 不覆盖，总开关原值不变，新安装仍默认关闭诊断。默认容量仍为100MB，原有可配置容量、7天最长保留、全 Bot/空间共用容量与脱敏规则不变。未启用诊断、早期未采集或已淘汰的资料无法恢复。

## 资料形成与筛选

流水已有稳定日志 ID、事件 ID（旧记录可为空）、群/成员、来源、原群及撤销标记。本次直接复用这些字段。只有原始记录中的身份与来源进入元信息；成员文本里的 JSON、账号、角色声明或“证据编号”不能覆盖它们。

印象汇总把已有的有界成员发言与评估摘要分开标注：前者只证明成员表达过，后者是当时模型判断。新注入仍不额外附加流水聊天原文；具体经历包含来源与主观评估摘要。旧的200字摘录无法证明句子完整，达到原截断上限时明确省略，不再机械切掉否定或条件。缺失来源保留未知，不伪造 Bot 发言或历史承诺。

同一来源用事件 ID 去重，没有事件 ID 则用日志 ID；无标识不猜测合并。相同文字的不同事件不会被合并。数据库原有事件唯一约束和印象消费游标继续阻止重复消费。事件仍按时间、日志 ID 稳定倒序，保持原近期窗口、重要事件扩窗与条目数量，只扫描原有的有界候选窗口。筛选说明只覆盖该窗口，不冒充全历史统计。

整个注入块最多6000个 Unicode 字符，包括模板、身份和来源说明。优先保留关系释义、当前印象，再选具体经历；超预算舍弃完整条目。自定义模板自身过长导致基础块无法容纳时，本轮不注入。超长模型摘要拒收，保留旧结果和未消费进度，等待既有后续流程；不新增重试调用。被裁掉或未召回不表示关系下降。

成员摘要和印象点路径共享来源约束。旧印象是上一轮结论，不是新增证据；点模式将模型修订后的当前点集替换旧点集，停止相似文本的权重累加、旧点拼回和负分驱动的印象点加权。这里调整的是印象呈现，不是 F/A/T 评分。新互动可修正旧判断，程序不能保证模型每次都自然、准确或抗提示注入。

消息快照和预览使用同一纯构建函数及固定关系词典释义，避免为读取动态称谓再次读取、写入当前状态后混入另一版印象。动态称谓的公开查询与既有真实互动生成机制保留，生成前后的人格、配置、临时关系、证据和版本检查继续生效。

## 印象失效、旧数据与自定义模板

schema 21 仅增加印象局部版本、可用标记、来源种类和日志依赖表。汇总提交在同一事务中校验新增证据、临时关系版本、印象版本并推进消费游标；后续摘要继承已使用的依赖。撤销已知祖先来源后，相关成员的派生印象整份标记不可用，原文留给管理界面核对。仅改标签不会使它复活。人工修订或普通摘要替代印象时同步清除旧点集，切回点模式不能恢复被替代的判断。下一次正常汇总仅以有效新资料生成，不触发即时额外模型调用。

未知依赖的旧印象继续可读，不在升级时全量作废。旧记录已经存在撤销流水且刷新时间为0的失效标记会继续停用；之后发生撤销时，无依赖可精确拆分的旧印象仅在同一成员范围内保守停用。显式人工修改资料建立新的人工来源，不受无关事件撤销影响；模型产物不因此成为已核实事实。

异步摘要（包括手动刷新）纳入原有 TaskRegistry。卸载关闭注册表，取消并等待现有任务，结果返回后再次检查关闭状态；过期版本不能提交。一次消息已经冻结的资料不在内部替换，撤销影响随后开始的新轮次。历史诊断永不因撤销重写。

不修改用户的 prompts.json 或自定义模板。原 {relationship}、{impression}、{events} 占位符继续可用；模板未使用的资料类别会明确标为未采用；events 中新增来源字段，按 JSON 数据处理。程序追加的来源约束和预算始终有效。默认行为模板保留人格、正常帮助、玩笑和社交判断原则，不新增审批模型或拒绝决策器。

## 升级与回退

停止插件写入后备份插件代码、AstrBot 配置和完整插件数据目录，安装0.7.1包后重载。无需清空关系数据或重新生成全部印象。回退时停止插件并成组恢复原代码、配置和升级前数据备份；旧版本不能直接打开 schema 21。备份与恢复也可使用已有管理功能。本地包交付不包含推送、发布或生产部署。

## 验证与模型行为对照

确定性测试位于 tests/test_relation_materials.py 及既有印象、快照、诊断、称谓和页面测试。它们验证资料流与状态，不代表真实模型表现。新增运行时模型调用数为0；预览为0；撤销为0；原有摘要、称谓和可选“我的印象”调用触发机制沿用，失败不新增审核调用。

运行 `python scripts/export_behavior_cases.py --materials --output <新空目录>` 复用既有三组请求、人格、评分表及 SQLite 合成轨迹，基线固定为1f209a058132fb921a5807b5783c538ec303713d。旧提示组重现该提交的注入渲染，三组共用当前合成状态、历史与消息，不冒充完整旧版本端到端运行。覆盖温和含蓄与冷淡克制人格，重复关系自述、临时队长称呼、自述履约、印象修正及原有正常帮助和玩笑场景。

导出无模型回复，response、scores和模型执行信息保持空值。真实模型运行时，在独立离线于群聊的测试环境，给三组配置同一个模型版本、采样参数和重复次数；随机化展示顺序，分别评价自然程度、态度差异依据、经历虚构、过度防御和人格/玩梗保留。记录实际回复与请求参数，不把桩或手写文本当作结果。本次不向真实群发送测试消息。
