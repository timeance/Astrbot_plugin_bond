# PR-1：Bot 与关系作用域隔离

本阶段沿用上游单值关系语义，先验证存储与所有调用入口的隔离。三维关系、分级评估、人格中立提示词与无分数公开查询分别在后续阶段验收。

## 数据目录

```text
data/plugin_data/astrbot_plugin_bond/
  bots/
    {真实 Bot 账号}/
      group.db
      global.db
  backups/
```

身份来自平台事件的 `get_self_id()`，只接受 ASCII 正整数。文件路径不接受聊天正文、昵称、客户端路径或模型输出。首次接收该 Bot 的有效群事件时初始化两个独立数据库；不会导入旧 `bond.db` 或 Xinxian 数据库。

`per_group` 的主键保留群和成员；`global` 在独立数据库中使用固定逻辑群键 `__global__`。关系、冷却、每日额度、流水、印象和标签均跟随选定数据库。全局库另存成员在各群出现的索引，群内排行榜仅包含该群已观察到的成员。

## 配置与操作

AstrBot 插件配置中的 `bot_scope_modes` 保存各 Bot 当前模式，格式为 JSON 对象，默认 `{}`，未设置的 Bot 使用 `per_group`。优先在插件面板选择 Bot 后切换模式。切换仅改变随后请求的路由，不复制、合并、清空或换算任何已有记录。

后台任务在排队时绑定服务实例、Bot、模式、群、成员、平台、消息 ID 和会话来源。模式切换后完成的任务仍写原来的数据库。切换 Bot 或空间后，管理页面清除原空间的详情和撤销确认。

`ignored_bot_ids` 用于配置同群其他机器人的账号。自身账号和已有可信 Bot 数据空间的账号也会被忽略。未提供真实账号的适配器不会根据昵称或正文创建数据库。

全局模式的旧关系注入、近期会话上下文和自动印象汇总保持关闭，避免将跨群历史原文带入回复；后续增加明确来源与作用域保护后再启用。手动管理本地印象仍可用。

跨插件门面改为要求显式 Bot 与作用域的只读 `BondFacade`，不提供无 Bot 身份的通用写入方法。群内不允许在全局模式下执行无目标的整群清空。

## 升级、备份与回滚

升级前停用插件，备份代码、AstrBot 插件配置和整个 Bond 数据目录。旧单库保留原位；本阶段不自动迁移旧关系。首次启动没有 Bot 事件时不创建一个共享的默认数据库。

在线备份通过 SQLite backup API 获取选定 Bot/空间的一致快照。恢复必须选择同一 Bot/空间的备份，校验完整性与受支持的 schema，并保留恢复前的快照。恢复一个空间不能影响另外一个空间或其他 Bot。

回滚到 PR-0 时先停用插件，恢复对应的旧代码、旧配置与旧单库备份。新分库保持归档，不让旧代码直接打开新版结构。不自动将两种模式并回单库。

## 验证边界

离线测试验证上游数值事务、撤销、四库隔离、模式往返与重启、在飞任务、全局本群排行榜和非法路径。独立真实框架检查验证 AstrBot 装配、服务端权限与生命周期，不连接真实 Bot 或模型，不替代真实群聊和完整管理面板验收。

2026-10-31：Python 3.12.14 下 260 项离线测试通过。AstrBot 4.28.0 独立进程检查通过：两个 Bot/四库、模式持久化、事件对象变更与在飞评估固定路由、10 个页面 API、未认证请求拒绝、备份恢复、卸载。认证测试模拟宿主中间件写入的 `g.username`，未测试完整 HTTP 登录流程；前端仅完成语法检查，未作浏览器视觉验收。

继承的任务注册表在卸载等待超时后仍可能有未结束任务；当前写事务为同步临界区且 Provider 链不抑制取消，但后续分级评估需要进一步限制队列并封闭卸载后的写入。此项在 PR-3 一并处理，不据本阶段测试宣称任意第三方 Provider 都能及时取消。
