## 看似读取但有副作用的入口

- `FavorService.get` / `get_relation` 的有效分数是投影，不因普通读取写衰减或保温；但它们先走 `override_state`，临时覆盖到期时会结束覆盖并写审计/时间锚。
- `temporary_state` 同样可能结束到期覆盖；排行、成员详情及部分管理查询间接调用上述入口，不能直接用作纯预览。
- `read_relation_title` / `TitleService.read` 本身不调用模型，但 `_track` 会同步观察基线、缓存有效性和模式状态；不能作为无副作用预览，也不能在冻结分数后再读取另一版印象。
- `maybe_refresh` 是既有自动汇总调度，`refresh_now` 是显式刷新并调用模型；“我的印象”在 summary 模式会调用会话模型，不能复用作预览。
- `RuntimeService.select` 可以创建数据库、迁移及装配服务；预览改用 `peek`。`PromptService.resolve`、固定关系释义、SQLite `read_relation_snapshot` 及纯资料构建不产生上述写入。

因此本轮注入与预览统一使用同一个事务读取快照和固定关系词典释义。动态称谓的查询、观察与原有真实互动生成继续保留。此选择避免扩展动态称谓读取接口，且不会新增模型调用。

## 四档核实与差异

四档依次为 assessment（结构化评估）、raw（原文与评估，并可记录 Bot 回复）、evaluation（再加评估输入/输出）、full（再加 Bond 观察到的主回复请求）。基线默认实际上是第一档，与任务中的“默认第二档”不一致。本次按当前要求把缺省值改为第二档，已有显式选择保留，诊断总开关和默认100MB不变。旧记录未记录的资料不回填。关闭、容量淘汰、清除代次及选择性清除沿用原机制。

## 程序保证与模型期待

程序保证可信标识不可被文本覆盖、基于 ID 去重、无效材料停止用于新轮次、整条预算裁剪、局部版本校验、同轮冻结、预览零业务写入和诊断分档。提示规则要求自述保留自述属性、允许修正旧印象、角色扮演不升格为永久关系，并保持人格与正常帮助；这不能证明真实模型不会误判或被提示注入影响。

回归用例使用固定时间、合成账号、真实 SQLite 和可控模型桩，无真实群消息。数学核心、独立维护、限额、托底、舍入、半衰期及被动增长用原有测试验证，不修改这些测试的期望。完整命令、实际结果及未运行条件见交付验证报告。

## 已知限制

- 来源依赖是整份印象级别，不推测模型究竟使用了其中哪一句；继承旧结论时保留祖先来源。撤销后无法可靠拆分时停用整份结果，等待正常流程的新材料。
- 老印象无可还原的完整来源，默认兼容读取；同成员发生相关撤销时保守停用。不会清空其他成员或虚构历史证据。
- 原流水摘录的200字上限没有完整性标志，达到该上限一律明确省略，可能少提供完整但恰好200字的材料。
- 选择理由只解释原有有界候选集合，不声称查遍历史。纯字符预算不是精确 token 预算。
- 真实 AstrBot 框架、管理页浏览器交互、模型自然程度和线上插件顺序仍需实际环境验收；已有离线桩/页面测试不等同于这些验收。
