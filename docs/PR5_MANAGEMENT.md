# 管理面板与公开查询

在 AstrBot 插件管理中打开 Bond 原生页面。先选择当前 OneBot 已连接、收到过可信事件或已有本地记录的 Bot，再选择按群或全局空间。空间切换只改变路由，不复制或合并历史。全局空间查看、编辑成员时仍需选择真实群，不能把内部 `__global__` 当作群 ID。

成员列表显示熟悉度、亲近度、信任度和组合称谓。默认每页50条，可选30/50/100/200。已观察且三维有效值全零的成员默认折叠，显示折叠数量，可展开；按QQ账号搜索包含折叠成员。临时关系非零时不会因正式值为零而隐藏，未观察的人工零值记录仍显示。按群空间的“全部群”可能包含同一人在不同群的多条记录。

详情可调整三维数值、填写理由、修改本地印象与标签。数值调整、资料修改和撤销记录操作账号；数值变动可以预览并撤销，资料审计不作为数值事件撤销。现有流水与备份恢复入口继续使用所选数据库。

流水默认展示F/A/T增量，可切换到某一维度，只列出该维度有已知非零变化的事件。可同时选择“仅自动评估”；评估页的维度入口进入同一流水页。选择维度不关闭评分，也不改变撤销范围：撤销始终作用于整个事件。旧流水只有亲近度时，F/T显示“未知”；历史前后值仅保留亲近度，不用当前值反推其他维度历史。

提示词页分别选择评估或行为模板，以及全局设置或当前 Bot 的群覆盖。预览使用合成资料，不写入设置。恢复群默认后继承全局模板。保存会在服务端校验占位符，成功后立即生效。

AstrBot 插件配置通过下拉选择评估及复核 Provider。Bond 评估页设置超时、冷却、并发上限和大模型每日调用次数。保存后重载插件，所有 Bot 与作用域统一采用新配置；页面同时展示当前运行配置，包括实际运行并发上限；编辑或保存待重载设置不会将它显示成已经生效。未配置 Provider 或关闭评估时，关系查询与人工管理仍可使用。

统计按所选数据库汇总调用、状态和已知 Token。缺失用量显示“未提供”，货币费用不作估算。大模型次数预算在同一 Bot 的两个空间间合计，切换模式不能绕过限额。

普通群友使用 `/我的关系` 查看本人称谓，使用 `/好感排行` 查看本群前十名，按亲近度排序，不公开分值。LLM 工具采用相同规则，不能指定他人查询私有数值。跨插件只读 facade 也返回组合称谓，原 `level` 字段改为 `relation_title`。

所有面板接口先检查宿主写入的 `g.username`，未认证返回 401。客户端提交的用户名或管理员标志不授予权限。此版本沿用 AstrBot Dashboard 的管理账号边界。

详细设置默认展开基础项：默认群／全局关系模式、主人 QQ 和群白名单。默认模式用于未在页面顶部单独选择过模式的 Bot；已有 Bot 专属设置优先，不随默认值覆盖。主人标记仅用于关系称呼，服从当前人格，不授予管理权限、不豁免评分。群白名单与 AstrBot 插件配置共用同一字段，留空对所有群生效；填写后只在所列群启用关系记录、评估、注入和群聊查询。保存后重载生效，不删除已有数据，后台管理员仍可管理历史。

当前沿用 schema 15，本次分页与维度展示不变更数据库结构。升级前备份插件配置和完整数据目录；回滚到同 schema 代码时保留数据库，回滚旧 schema 版本须同时恢复升级前备份。不要运行旧代码直接读取新结构。

## 成员与流水查询参数

认证与Bot/作用域选择沿用原接口。`users` 使用 `page`（从1开始）、`page_size`（30/50/100/200，默认50）、`search`（账号子串）和 `include_zero`（0/1）进行查询，响应包含 `page/pages/total/matched_count/collapsed_count`。旧面板使用的 `limit` 已由分页参数替代；升级时应同时加载新页面资源。搜索时包含折叠记录，`total`为筛选后可分页数量，`matched_count`还包括折叠数量。

`logs` 可加 `dimension=familiarity|affinity|trust` 与 `source=judge`；省略即不过滤。筛选在条数限制之前执行。成员排序则先读取候选的有效关系（含衰减、临时覆盖）再筛选和分页；这是正确性取舍，不表示数据库读取量随页大小下降。当前没有新增索引、缓存或持久化摘要，大规模性能与浏览器实际操作尚未验收。
