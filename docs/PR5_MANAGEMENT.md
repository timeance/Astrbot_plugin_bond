# 管理面板与公开查询

在 AstrBot 插件管理中打开 Bond 原生页面。先选择产生过可信事件的 Bot，再选择按群或全局空间。空间切换只改变路由，不复制或合并历史。全局空间查看、编辑成员时仍需选择真实群，不能把内部 `__global__` 当作群 ID。

成员列表显示熟悉度、亲近度、信任度和组合称谓。详情可调整三维数值、填写理由、修改本地印象与标签。数值调整、资料修改和撤销记录操作账号；数值变动可以预览并撤销，资料审计不作为数值事件撤销。现有流水与备份恢复入口继续使用所选数据库。

提示词页分别选择评估或行为模板，以及全局设置或当前 Bot 的群覆盖。预览使用合成资料，不写入设置。恢复群默认后继承全局模板。保存会在服务端校验占位符，成功后立即生效。

评估页设置 AstrBot Provider ID、超时、冷却、并发上限和大模型每日调用次数。保存后重载插件，所有 Bot 与作用域统一采用新配置；页面同时展示当前运行配置。未配置 Provider 或关闭评估时，关系查询与人工管理仍可使用。

统计按所选数据库汇总调用、状态和已知 Token。缺失用量显示“未提供”，货币费用不作估算。大模型次数预算在同一 Bot 的两个空间间合计，切换模式不能绕过限额。

普通群友使用 `/我的关系` 查看本人称谓，使用 `/好感排行` 查看本群前十名，按亲近度排序，不公开分值。LLM 工具采用相同规则，不能指定他人查询私有数值。跨插件只读 facade 也返回组合称谓，原 `level` 字段改为 `relation_title`。

所有面板接口先检查宿主写入的 `g.username`，未认证返回 401。客户端提交的用户名或管理员标志不授予权限。此版本沿用 AstrBot Dashboard 的管理账号边界。

本阶段沿用 schema 13。升级前备份插件配置和完整数据目录；回滚到同 schema 代码时保留数据库，回滚旧 schema 版本须同时恢复升级前备份。不要运行旧代码直接读取新结构。
