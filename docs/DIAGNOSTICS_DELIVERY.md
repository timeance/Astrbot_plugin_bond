# Bond 0.5.1 交付说明

## 本次变化

在 0.5.0 关系升级基础上新增四档诊断：「评估记录」「原文+评估」「评估上下文」「完整上下文」，诊断总开关仍默认关闭，详细程度默认第一档「评估记录」。已有 diagnostics.enabled=true 但未保存 detail_level 的配置仍只记录评估信息；显式选择的 raw、evaluation 或 full 不变。容量默认 100 MB，可配置 1–10000 MB，全部 Bot 和关系空间共用。设置页显示当前空间及全部诊断实际占用。

「完整上下文」指 Bond 在请求钩子时可观察到的回复模型输入，不保证覆盖后续插件或 Provider 修改。不会新增模型调用。诊断保存失败不改变正式关系操作。

清除诊断同时清除其中聊天和上下文副本，并阻止清除前在途任务重新写回；不会清除正式评估流水、关系、印象或 AstrBot 聊天历史。启动和每小时检查过期文件；超过容量提前轮转。插件未运行时无法执行定期清理。

## 安装与升级

1. 备份当前插件代码、配置和整个插件数据目录。
2. 停止或卸载插件实例，用安装 ZIP 替换插件代码并重新加载。不要删除原数据目录。
3. 在详细设置的关系诊断中选择档位、设置容量，按需开启总开关。
4. 发送一条相关消息，查看占用变化并导出诊断文件检查。

从 0.5.0 升级不新增数据库迁移，仍为 schema 18。从 0.4.4 升级先应用独立维护迁移（0.4.5），再应用 0.5.0 消息快照与行为指导，见 MAINTENANCE_UPGRADE.md 与 P0_DELIVERY.md。回退至 0.4.4 必须使用升级前备份，不可直接让旧代码读取 schema 18。

安装包只含运行所需文件和说明；源码包另外包含测试、脚本及开发材料。通过导入 PR 等待维护者合并，未部署或发布。离线与框架检查使用合成消息，不代表已在真实 QQ 群或真实 Provider 运行。

## 本次验证

JSON 字符串形式的常见凭据字段（包括工具结果 content）在写盘前按结构脱敏，数字、对象、数组、布尔与 null 值同样覆盖，转义字段名也会识别，解码后的文本逐项过滤凭据、媒体和URL查询参数后再编码，保留合法结构；异常数值和不支持的对象替换为 null 后按相同预算计费，避免有效行在导出复检时被误判为损坏。容器和列表元素均消耗预算，JSON 解析超限、不完整、文本过滤破坏结构或转义后的大小超过剩余预算时整段省略，保证已写入的正常记录可以导出。文本仅按已知模式处理，仍不承诺完整自动脱敏。

- 诊断聚焦离线回归通过，覆盖实际写盘再导出、JSON 引号与转义、接近预算、内容复检幂等、异常对象、深度及宽度截断；历史未脱敏行被拒绝导出并计入缺口。
- 真实 AstrBot 4.28.0 配置加载和诊断装配检查通过：缺失档位补为 assessment，显式 raw/evaluation/full 保留；2 Bot × 2 空间、认证拒绝、选择性清除和关闭后历史管理通过。
- 修改的 Python 文件通过锁定版本 Black、Ruff 格式检查，工程元数据检查通过。
- 所有输入均为合成数据。未运行真实 QQ、真实聊天 Provider 或完整宿主浏览器会话；最终整包验收以导入 PR 的检查记录为准。
