# Bond 0.5.0 升级说明

## 本次变化

- 关系与人格共同影响社交选择，不把所有要求一律接受，也不把陌生人正常求助一律拒绝。
- 保留符合角色的玩笑、熟悉感和共同话题；不凭高关系分数编造经历。
- 熟悉、亲近、信任分别维护，普通问答不再让全部关系一起保温。
- 标准群消息回复使用入场时的完整关系资料，避免后台处理快慢造成同轮状态不一致。
- 升级保留历史关系，支持切回旧维护方式；不覆盖自定义行为模板。

## 安装前先备份

1. 停用 Bond，备份现有插件代码、AstrBot 插件配置及整个 `data/plugin_data/astrbot_plugin_bond/` 数据目录。
2. 将安装包解压到 `data/plugins/astrbot_plugin_bond/`，确认 `main.py` 直接位于该目录，不要多套一层文件夹。保留数据目录和已有配置。
3. 重载插件，检查版本为 0.5.0、已有成员关系仍在。已有数据库会升级到 schema 18，首次重载会结算已有空间并切换维护策略。
4. 现有自动评估、注入开关不变。要让新版默认行为指导生效，使用默认行为模板；自定义模板不会被偷偷替换，可自行审阅后选择是否恢复默认。

默认 `decay.maintenance_strategy=independent`。如果试用后想保留旧版统一保温方式，在关系变化设置中改为 `legacy` 并重载。它只改变未来维护逻辑，不倒带历史分值，不撤销行为提示或快照修复。

**切回旧逻辑不等于降级代码。** 若要重新安装 0.4.4，必须同时恢复升级前匹配的代码、配置和数据备份；旧版不能直接打开 schema 18。

## 建议先在测试群观察

先比较正常求助、熟人玩笑、普通昵称、亲密身份要求及连续数日互动。关注正常交流是否变得扫兴，以及每天聊天是否产生不自然的疏远感。有问题时记录实际模型、人格、设置和例子，不要只看关系数值。

工程测试及真实框架装配已完成，详细结果见 [验收记录](ACCEPTANCE.md)。**真实聊天模型的趣味性和群聊效果尚未验证**，不能保证所有模型或所有场景都优于旧版。完整源码包中的 [行为评测材料](P0_BEHAVIOR_EVALUATION.md) 可用于后续比较，不会自动调用模型或产生费用。

## 交付边界

本次通过三个堆叠 PR 交付，维护功能为0.4.5，本阶段行为与消息快照为0.5.0，详细诊断采集随后单独审核。PR不等于Release或线上部署；安装包需在合并并明确授权发布后按仓库打包流程生成。

资料按同一SQLite短读事务读取，再绑定可信Bot/空间/群/成员与读取时点；证据保留发生时间。标准入口之外的请求只能在首次请求钩子冻结，无法保证早于第三方写入。真实runner到离线Provider已另有独立smoke入口，具体执行结果以本PR验收记录为准，未运行完整群聊pipeline。
