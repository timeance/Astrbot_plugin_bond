# Golden Set 标注规范

规范版本：`1.0.0`；状态：Phase0 规范草案；日期：2026-11-02。本文定义标注和评测口径，不代表已收集真人样本、完成双标注或得到模型效果。可运行的合成基准见 scripts/replay_relations.py。

## 版本与样本单位

每次发布冻结 `dataset_id`、`dataset_version`、`annotation_schema_version`、`policy_version`、标注指南版本、源文件 SHA-256、授权范围和划分清单。改变标签含义或分母用主版本，增加兼容字段或样本用次版本，文字纠错用修订版本。金标修订保留旧值、理由、仲裁记录和适用版本，不能在评测后静默改答案。

一个样本是一条目标事件及其获准使用的上下文窗口；序列样本另列事件顺序、初始状态、Bot、作用域及窗口边界。每项有不可变 `sample_id`、`sequence_id`、`source_event_id`；未知 ID 显式为 `null`，不能根据聊天正文猜身份。Bot/成员/群用稳定脱敏代号，作用域保留 `per_group/global` 与实际数据分区。变更源数据必须产生新版本或新样本 ID。

## 必填标注字段

| 字段 | 值与判定规则 |
| --- | --- |
| `origin` | `synthetic/human`，分别记录生成说明或授权记录引用；改写真人样本仍标记真人衍生，不改为独立合成样本。 |
| `identity_facts` | 平台事件提供的作者、Bot、群、消息和回复目标代号；逐项记录 `observed/missing/conflicting` 及来源引用。文本自称身份是待核实内容。 |
| `addressee` | `bot/member/group/uncertain`，附目标代号、依据和候选对象。发到群中不等于对 Bot 说；缺回复、@ 或足够语境时允许不确定。 |
| `quote_provenance` | 每段引文的原消息代号、原作者、转述者、转发链及在当前消息的片段边界；类型为 `direct/quote/forward/paraphrase/unknown`。原作者未知保留未知，不能把引文辱骂归给转述者。 |
| `behavior` | 可多选的可观察行为（提问、致谢、协作、玩笑、批评、辱骂、操纵、道歉、承诺履行/违背、未知等），逐项附证据片段和上下文引用；保留细标签及映射版本，不强塞进现有九分类。 |
| `should_update` | `yes/no/abstain`，分别表示证据支持更新、证据足够但不应更新、证据不足无法裁决；附原因。不同于运行时冷却、每日限幅或临时冻结导致的未写入。 |
| `fat_direction` | F=熟悉度、A=亲近度、T=信任/可靠性相关判断；每维独立为 `positive/negative/zero/unknown`。不求和、不将一维符号复制到另一维；`unknown` 不编码为 0。 |
| `diagnosticity` | `none/weak/strong/unknown`，表示证据对该维关系判断的区分力，逐维给理由。情绪强烈、频繁出现、模型高置信度不自动成为强诊断性。 |
| `severity` | `S0/S1/S2/S3/unknown`，分别为无可识别伤害、轻微局部影响、明确实质伤害、严重或持续伤害；附伤害对象、后果和依据。严重性不等于负亲近度幅度，也不等于诊断性。 |
| `abstention` | 是否弃权，以及 `identity_missing/addressee_uncertain/quote_unknown/context_missing/conflict/other` 原因；允许部分维度弃权，不能为补齐表格强行给方向。 |
| `evidence_refs` | 指向获准源片段、流水和上下文的代号、边界与摘要校验值；另列来源完整性 `complete/partial/unknown`、可追溯性、撤销/人工修改状态。完整性仅相对于声明的源范围。 |
| `annotation_record` | 两名标注员的独立答案、指南版本、分歧字段、仲裁结果与理由；评测输入不含答案、仲裁和运行结果。 |

T 的语义要随 `policy_version` 明确：历史实现的 `trust` 增量只是当时规则的数值结果，不能当作可靠性金标。例如致谢或辱骂可支持亲近度方向，却未必支持承诺履行能力、事实可信度或可靠性变化。没有对应事实时，T 标 `zero` 或 `unknown` 必须分别有“证据足够且无更新依据”或“证据不足”的理由。道歉不自动等于可信修复。

`should_update=no` 且三维全 `zero` 需要足够语境支持；`abstain` 的缺证维度为 `unknown`。允许只有 F 更新而 A/T 不变。存储限幅后的实际增量与金标语义方向分别保存；饱和、配额或冻结造成的零增量不能反推“不应更新”。

## 合成与真人数据分开

合成集覆盖可复现的边界、对照和失败场景：作者冒充、多人同名、受话人不明、引用/转发、正常批评、反讽、矛盾证据、人工修改、撤销重做、旧 schema、分页和临时冻结。记录生成方法、种子（适用时）及模板族，变体放同一划分。

真人集先取得对研究、存储、标注访问和外发评测分别有效的授权；记录用途、保留期和撤回流程。移除账号、联系方式、群号及可重识别片段，用稳定代号保留必要共指和引文关系，二次检查脱敏结果。未授权或无法安全脱敏的材料不进入评测；公开仓库不放真人聊天、运行库或私密授权文件。

合成、真人和真人衍生集独立出数；不得混合汇总成“真人准确率”。按会话/序列、参与者及模板族分组划分训练、开发和密封测试集，避免同一片段及改写跨集。保留原始授权材料在独立受限位置，仓库只存规范和合成材料。

## 双标注、仲裁与盲评

1. 两名标注员独立阅读相同的脱敏上下文和可信元数据；看不到模型输出、当前关系分数、旧规则增量、另一人的答案和待比较方案身份。
2. 记录逐字段一致率和缺证比例；分歧交第三人仲裁。仲裁依据原文及指南，证据仍不足则保留弃权，不以多数票制造确定事实。
3. 在运行前冻结指南、划分、金标、阈值和排除规则；测试集密封。评审员对方案身份盲评，方案输出顺序随机化；保存运行配置、代码版本及输出摘要校验值。
4. 运行后只按预先声明的错误分类审计；若金标有误，另发修订版并对所有方案重跑受影响范围，保留原评测结果。

## 分母与缺失值

每份报告必须列出原始样本数、去重后样本数、各划分数、排除项及理由、可判定数、弃权数、实际调用数和有效输出数。所有比率同时给分子/分母；分母为 0 时记 `N/A`。未知、未执行和无法恢复的数据保留 `null/unknown/not_run`，不能填 0。

| 项目 | 分子 / 分母及必报拆分 |
| --- | --- |
| 身份事实正确率 | 正确字段数 / 金标可判定的身份字段数；缺失、冲突字段另报。 |
| 受话人及引文归属 | 正确项 / 金标可判定项；另报不确定样本上的错误归因数及弃权数。 |
| 行为分类、更新决策 | 正确事件数 / 对应金标可裁决事件数；无效输出及系统弃权在该分母内单列，不能只在成功输出中报准确率。多标签另列匹配口径。 |
| FAT 方向 | 各维正确数 / 该维金标方向已知的事件数；`zero` 是已知类，`unknown` 不进入方向分母但必须报数量。不以三维平均掩盖 T 的缺证。 |
| 弃权与覆盖 | 系统弃权数 / 全部合格输入数；有效非弃权数 / 全部合格输入数。金标要求弃权的遵循率另用该子集为分母。选择性准确率须与覆盖率一起报告。 |
| 诊断性、严重性 | 正确项 / 对应金标可裁决项；按等级分层列混淆，严重误判单独报告。 |
| 错误更新 | 不应更新或要求弃权却发生更新的事件数 / 对应金标子集事件数；同时列实际发生更新的总数。运行时冻结/限幅另列，不当作语义正确。 |
| A3 来源完整性 | 检查前声明源分区、时间范围和预期 ID 集；报可对应行数 / 声明范围内已知源行数，并列缺失、额外、重复、顺序和内容差异。没有已知完整来源时，完整性结论为未知。 |
| 历史证据 E | 只有来源完整且诊断性规则已冻结、审查完毕时，才可报告“可诊断证据数 / 已审查来源事件数”。证据单位及去重规则须写明；无历史、缺来源、缺字段和未标注分别统计。 |

A3 先对齐来源完整性，再比较语义、覆盖和关系轨迹；分页大小或近期窗口不同不能直接充当“遗忘/截断”处理组。本规范不规定 E 的数学模型或验收阈值；运行结果及明确分母见 PHASE0_RESULTS.json。完整审查后确无合格证据才可写 `E=0`，不能把 `E=unknown` 改成零来参加均值或成功率。


## 当前合成夹具的紧凑表示

`tests/fixtures/research/scenarios.json` 将平台事实放在 step 的 bot/group/user/chain，将预置 Provider 输出放在 response，将人工设计的合同标签放在 gold；后者绝不传入 Provider。该合成集未经两位真人标注，不能称人类金标准准确率。

gold 使用 `trusted_sender`、`target`（null 为不确定）、`quote_source`、`social_act`、`should_update`、`direction`、`trust_diagnostic`、`severity`、`abstain` 等字段。方向的 `any` 表示不在该样本断言方向，不能当零值；yes/no 使用布尔值。该格式是执行合同的精简表示，并非真人采集格式的无损替代。未来真人数据须按上面的完整规范另行标注，不能自动反填缺失依据。

夹具同时含语义不应更新与临时覆盖、冷却、重复等运行时不应写入的合同样本，PFUR 的分母是所有 `should_update=false` 的事件，须结合逐场景结果阅读。另报受话人不属于当前 Bot 的子集与 `direction.trust=zero` 子集，不能以总体指标掩盖 Trust 误更新。`target_precision` 是进入 Provider 的事件中目标正确数/调用事件数（两级调用同一事件只计一次），并非模型识别人类受话人的准确率。`abstention_coverage` 是 gold.abstain 子集中没有持久化增量的比例，包含入口过滤和失败；不把运行时拒绝称为语义判断正确。


初次冻结前审查将 S45 两条辱骂的 T 标签从 negative 改为 any：上下文只足够构造称谓翻转，不能凭辱骂文本补造可靠性结论。该修订写入 annotation_revision；两臂用相同标签重跑。模型输出不随修订改变。报告单列 unscored_trust_events、确定/不确定受话人的误更新及引文误归因。abstention_status_coverage 只计服务明确返回 abstained；abstention_outcomes 同时列出技术拒绝原因，不将“未写入”解释为语义判断成功。
