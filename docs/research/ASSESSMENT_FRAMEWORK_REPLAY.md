## 方法

## 可支持的结论

- 每日60个候选与30个候选得到同样轨迹；调用上限约束实际生效，180天均为5400次初评。不是60次互动机会。
- 每日仅一次普通问答时，A/T保持0；友好分类也不直接增信。
- Galgame会更早到达高F区间；高段仍保留微小增长，同时受到F60天衰减约束。每日5个候选下，第30天F/A约为34.4/32.4，第180天约55/50.8；不是持续线性增长。
- 所有结果依赖这里明确给定的模型输出。把问候误判为新的友好互动仍可能加分，框架不以关键词改写模型分类。
- 窗口并发、失败/超时、重复ID、三维衰减、正负基线停止范围、临时关系及撤销由相邻单元/集成测试独立覆盖；本轨迹不替代那些故障用例。

## 重现与边界

```text
python scripts/replay_framework.py --output <空目录A>
python scripts/replay_framework.py --output <空目录B>
```

两次 results.json 完全一致，SHA-256：`1c0e2c1aef21054158b6a4b4ed24f5aa5575d8605dd09b4b07f7450ce15490a5`。模型调用次数是预置Provider的实际调用计数；真实Token、模型语义误判率、真人体验和主回复延迟未测。

生产路径复用原有SQLite和事务，不新增关系维度、数据库或奖励队列。分段和数值变换是固定数量运算；上下文内存限制为128个成员会话、各最多20条，输入另有条数/字符限制。调用查询使用日期/窗口索引，仅统计相关范围；旧净额补齐只在旧账本首次使用当日时查询该日流水，不在每次互动扫描完整历史。
