# 久别旧识：保留基础，暂不增加专用回暖状态

2026-11-03。结论：本轮不加入“重逢后若干次加速”的生产机制。维护者明确优先控制复杂度；现有三维与写实/Galgame模板保留。没有新增字段、历史峰值保底、信任恢复奖励或额外运行查询。

## 研究支持到哪里

- Roberts 与 Dunbar（2015），[Managing Relationship Decay](https://pmc.ncbi.nlm.nih.gov/articles/PMC4626528/)，DOI `10.1007/s12110-015-9242-7`：18个月纵向研究中，维持联系的投入与友情质量变化有关。支持考虑互动中断与关系维持，但不提供聊天Bot的统一半衰期。
- Levin、Walter 与 Murnighan（2011卷期；2010在线发表），[Dormant Ties: The Value of Reconnecting](https://pubsonline.informs.org/doi/abs/10.1287/orsc.1100.0576)：职业求助场景中，以前的强关系重新联系可保有信任和共同视角。支持“旧识不必从陌生人重新开始”，不能推出固定几次聊天即可恢复亲近度。
- Rondi、Levin 与 De Massis（2023在线发表），[The Reconnection Process](https://pubsonline.informs.org/doi/10.1287/orsc.2023.1685)：重连需要回忆、近况交流与双方对关系的相近理解，也可能失败。不能将高熟悉度直接当作对方接受亲昵、原谅冒犯或增加信任的证据。

这些研究对象是人际关系，不是AstrBot评分系统。保留F/T、只让A温和衰减属于工程取舍，不是对论文参数的复刻；研究也不证明信任永远不变。

## 当前代码与可重复对照

`core/decay.py` 只计算亲近度随时间靠近0；`FavorService.get` 保留熟悉度和信任度。默认半衰期30天；既有旧亲近度档位托底保留，不能解释为所有三维词条永远最多下降两级。当前没有专用“旧识恢复倍率”。

运行 `python scripts/replay_reconnection.py --output <新的空目录>`。脚本使用真实FavorService/SQLite、固定时钟与预先分类的友好事件，没有QQ消息、模型判断或网络请求。种子为F60/A40/T20，离开前一次友好互动，90天后同日恢复三次，间隔180秒。

| 时点 | 写实 A | Galgame A |
| --- | --- | --- |
| 离开前 | 40.6 | 40.8 |
| 沉默90天 | 5.1 | 5.1 |
| 回来第1次友好互动 | 5.9 | 6.1 |
| 第2次 | 6.5 | 6.9 |
| 第3次 | 6.9 | 7.4 |

两条轨迹的Trust始终为20；F只按各自原有事件规则增加。称谓从“亲密的朋友”变为“放心的熟人”，三次后仍为“放心的熟人”。它验证了“亲近感淡化、旧识基础保留、不会快速回到原值”，没有验证真实语义质量。两次独立输出的逻辑JSON一致。

## 为什么不加连续回暖

`confirmed in code`：存储会在有效关系事件中结算亲近度衰减并重设时间锚。现有流水记录实际互动增量，不记录一份独立的“沉默损失预算”。临时关系结束会平移时间锚；部分旧标量写入不会生成普通变化流水。因此，最近几条流水的时间差和数值差不能在所有路径上可靠证明只是沉默造成的下降。

要支持重启后仍连续几次有限加速，需新增回暖额度/次数/时钟，并明确人工改值、撤销、重置、临时覆盖及配置变化时如何失效。只做一次加速虽可减少状态，却依赖重逢第一条被分类成何种事件，无法稳定表达所需体验。两者本轮均不采用，也不隐藏进现有三维JSON或复用半衰期字段。

以后仅在真实观察显示问题值得增加状态成本时重新提独立RFC。当前采用写实或Galgame的统一增长规则；重逢不额外增加F/T，不把低Trust的修复与久别后的A回升混为一谈。
