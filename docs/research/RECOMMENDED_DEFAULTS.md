# 0.3.4 推荐默认与短期观察

日期：2026-11-03。基于 main `2c236d40c862017782bf0f37bb549c1d9a4d1c3b`（0.3.3）。这是面向新用户的保守默认；2–3 天观察用于发现问题，不是到期自动切换配置。

## 为什么调整

原默认会把亲近度负向变化乘1.5；较大负面事件还可能压低随后48小时的正向增长。模型误分类时，这些后果会一起放大。半衰期按每次正向增长乘1.3，真实服务合成回放中六次正向事件就从30天到120天，不能据此说明长期关系已经稳定。

| 参数 | 0.3.3 缺省值 | 0.3.4 缺省值 | 取舍 |
| --- | ---: | ---: | --- |
| `economy.negative_weight` | 1.5 | 1 | 保留事件本身的负向变化，取消额外放大。 |
| `economy.repair_threshold` | 2 | 0 | 关闭事后亲近度增长压制；不代表开启了信任修复。 |
| `decay.half_life_growth` | 1.3 | 1 | 默认固定半衰期，避免短时连续示好延长保留。 |

保留基础半衰期30天、基线0、旧亲近度档位托底、当日增长递减0.25、噪声下限0.5，以及原有事件/日限幅。F初识分界1/5、感谢/示好/道歉T增量0继续有效。高级自定义预设和显式参数保留，只有缺失值使用新默认。初次使用仍须选择评估Provider并打开自动评估；注入、诊断与外部联动不擅自开启。

同日递减适用于全部正向亲近度事件，不能称为语义重复识别。负向误分类仍可能损失Trust，本次没有消除该风险，也没有自动识别实际改正并恢复Trust。

## 学术依据与适用范围

- Laurenceau、Barrett、Pietromonaco（1998），[Interpersonal intimacy as an interpersonal process](https://pubmed.ncbi.nlm.nih.gov/9599440/)。日记研究将亲密体验与自我表达、感知到的回应联系起来。它支持关注互动过程，不能推出“每条友好消息应加多少分”。本次不奖励更长消息、更多隐私披露，也不增加内容采集。
- Roberts、Dunbar（2015），[Managing Relationship Decay](https://doi.org/10.1007/s12110-015-9242-7)。18个月的人际关系跟踪发现友谊变化与维系行为有关；关系类型有差异。该研究没有为聊天Bot校准30天半衰期或1.3倍巩固。保留温和衰减、停止每次示好自动巩固，是工程取舍。
- Kim等（2004），[Removing the shadow of suspicion](https://pubmed.ncbi.nlm.nih.gov/14769123/)。实验中的信任修复受违背类型及后来证据影响，不能推出固定的道歉恢复比例或48小时惩罚窗口。默认关闭亲近度恢复抑制，并继续保持道歉不增加Trust。

这些论文研究的是特定人际场景；没有一组系数可直接作为Bond的心理学真值。本次没有新增概率维度、人格矩阵、事件状态机、跨日持久化字段或新的模型调用。

## 半衰期设置怎样作用于已有关系

采用无schema变更的读取规则：

- 巩固倍数为1：已有和新成员均使用**当前**基础半衰期，忽略旧记录中的巩固值；基础值上调、下调都能生效。
- 巩固倍数大于1：保留成员历史巩固值，读取与写入都限制在当前基础值和上限之间。基础值在此模式是下限，降低它不抹掉已经巩固的值；想统一使用指定天数，应把巩固倍数设为1。增长倍数仅用于今后的实际正向变化，不反推历史次数。
- 基础值最低5天，上限不应低于基础值；宿主直接配置若矛盾，基础值优先。页面拒绝低于5天的设置。
- 配置保存后须完整重载插件。读取会从原时间锚按新配置重算，因此显示值可能立即变化；不为这次配置变更批量改分、重置时间或追加事件。
- 正常后续写入仍先结算衰减，再原子提交三维变化、额度、冷却和流水。临时关系仍暂停自动修改与衰减，结束后平移暂停时间。
- 备份保留原值、时间锚和历史半衰期；恢复后按当前配置与时间计算，不保证重现备份当天的显示值。撤销仍反向撤销事件实际增量，不倒推过去的巩固。

`resolve_half_life` 只有固定次数的比较，没有新增查询或遍历。默认关闭恢复抑制后跳过为它读取最近50条流水的操作；既有当日计数仍沿用，不能宣称整个插件为O(1)。

附带修复三处已复现边界：标量分数封顶后实际零增长不得巩固；额度耗尽返回值须计入刚结束的临时暂停；临时关系期间撤销预览与执行均拒绝。

## 合成对照

`replay_recommended_defaults.py` 在当前代码上显式装配0.3.3旧参数和新参数，两臂输入相同。四个具名场景，每臂37次事件，共74次；使用固定时钟、真实FavorService和SQLite。事件已经预分类，不访问Provider，不能评价模型语义正确率。

| 检验 | 旧参数 | 新参数 |
| --- | --- | --- |
| 同日10次友好事件，最终F/A/T | 2 / 3 / 0 | 2 / 3 / 0 |
| 上述第6次事件后半衰期 | 120天 | 30天 |
| 上述轨迹第30天A（无后续互动） | 2.5 | 1.5 |
| 三天正常问答/批评，最终F/A/T | 2.1 / 0 / 0 | 2.1 / 0 / 0 |
| 单次普通insult分类的A增量 | -1.5 | -1 |
| 较重违背后单次道歉的A增量 | +0.3 | +0.7 |
| 违背→道歉→友好→再犯的最终T | -4 | -4 |

道歉不再额外受默认A恢复抑制，但其T增量仍为0。此表不把被预分类为insult的输入证明为真实侮辱，不能说明真人误判率下降；只证明同一误分类的额外A损失较小。

## 安装与2–3天观察

1. 备份配置与关系数据。新安装直接使用推荐增长/衰减；重装若保留旧配置，在“详细设置”填入推荐关系设置、检查、保存、重载。该按钮不自动保存，也不改变Provider、身份、群白名单、隐私开关。
2. 选择评估小Provider、开启评估；需要自然表达再开启关系注入。保持当前模型、人格、群范围和规则稳定；不同时切换多组参数。诊断由管理员明确开启，观察完可关闭。
3. 每天导出一次诊断并保留日期；第三天再导出完整窗口。先检查 `dropped`、`write_errors`、`expired_rows`、`evicted_rows`、`export_truncated` 和历史缺口未知。单次上限32768行，总容量20MiB；有缺口就只评价实际保留的部分。
4. 重点查看：中性沟通的A/T漂移、重复问候/夸奖轨迹、错误负向事件、初识所需有效互动、每百轮称谓翻转，以及Provider调用/Token/失败/超时/busy。耗时只能称对应诊断入口或模型调用耗时；主回复p50/p95未知。
5. 自愿提供少量脱敏争议样例，按 [Golden Set](GOLDEN_SET.md) 区分平台事实、人工判断和模型分类。未经标注，persistent_false_update_rate、target_precision、abstention_coverage和真人语义准确率均未知；展示样例数量和分子分母，不从分数变动猜准确率。
6. 重载后脱敏代号不相连，分开统计各加载会话。2–3天不足以验证30天半衰期、长期Trust修复或人格体验的统计优势；先修明确误更新，再逐项调节。

## 兼容与回滚

仍为schema15，无新增持久化字段、后台定时扫描或模型协议。已有显式参数不会被升级覆盖，历史分数和流水不重算；新配置只影响之后的有效值计算与正常写入。

需要恢复旧节奏，可恢复原配置（负向1.5、抑制阈值2、巩固1.3仅供还原原默认，不建议无观察直接切回），再重载。固定模式读取期间没有改写数据时，可恢复原配置重现对应有效值；一旦发生正常写入，不能靠回滚参数撤销已提交事件，应使用流水撤销或备份。诊断可独立关闭，旧格式仍可读。发布、合并和真实环境观察由维护者执行。
