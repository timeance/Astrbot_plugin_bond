# Phase 0：可重复证据基线

日期：2026-11-02。审计基线 `993e821bd127488820a0f639107f67c0c5402bf4`（main，0.2.1，schema 15）。本 PR 只增加研究、回放及验证，不改变生产默认值、协议或数据库。

## 问题与目标

当前致谢、示好和道歉会增加 Trust，而现有日志没有提供履约、诚实或可靠性事实的独立证明。多人消息只要含指向当前 Bot 的 @ 或 Reply 就可进入评估，冲突对象未先排除。研究先分别测量规则与入口，不把模型自报 confidence 当概率。

Bond 保持三维兼容核心：F 是可确认的有效交互暴露；A 是温暖/疏离；T 是涉及风险或脆弱性时的可靠性、诚实、守约及边界尊重。关系影响表达，不能改变人格核心、权限、主人身份、接话或主动发言策略。临时覆盖、真实 Bot 分库、群/全局空间及公开非数值称谓保持现有合同。

可用外部依据为随任务提供的 v1.1 交叉评审 RFC 与任务执行合同。两份原始 Deep Research 报告未取得；本合成集覆盖合同列出的反例，不声称逐例抄录或验证不可访问报告。外部建议不高于源码与 AGENTS.md。

## 方法

`tests/fixtures/research/scenarios.json` 包含 52 个具名场景。长序列以 turns 展开，每臂 1,201 条消息；固定壁钟、稳定 ID、空数据库。运行生产 `BondPlugin._on_group_msg` 方法体、监听器、AssessmentService、FavorService、SQLite/WAL；框架类型为离线桩。实际 AstrBot 转换和装配由独立进程分别检查。

两个实验臂使用相同输入、预置 Provider 输出和初始状态：
- baseline：冻结基线全部默认规则。
- model-a：仅显式覆盖 thanks/friendly/apology 的 trust=0，其余规则和限幅相同。省略 trust 字段不能覆盖旧默认值。

Provider 只收到生产协议里的 Bot、sender 和 text；gold 独立保存在结果，禁止借履约金标制造模型能识别修复的假象。合成失败、超时、伪造字段、原文证据缺失、预算不足、临时覆盖和忙时丢弃均走真实服务分支。并发门控只控制预置响应何时返回；普通调用超时与专门超时场景分开，避免机器调度速度决定逻辑结果。

运行命令见 [开发指南](../DEVELOPMENT.md)。每次空库运行输出逐事件 JSON、规则/配置/源码摘要、轨迹和中文报告。两次逻辑结果应相同；墙钟耗时独立存储，不进入确定性比较。后续代码改变时，所有实验臂使用当次源码路由；要与本 PR 冻结结果比较，不能将“旧规则+新入口”称为完整旧版本。

完整指标和分子/分母见 [PHASE0_RESULTS.json](PHASE0_RESULTS.json)，测试与实际命令见 [BASELINE.md](BASELINE.md)。PFUR 是不应写入的合同子集；Trust 误更新另用该维应为零的子集统计，不能以总体 PFUR 未变化掩盖礼貌增信问题。

单独的服务存储测试验证分页、窗口筛选、reset、undo、manual edit 和旧字段缺失，不能将其冒充模型语义场景。解释见 [历史审计](HISTORY_AUDIT.md)；标注、脱敏和盲评见 [Golden Set](GOLDEN_SET.md)。

## 准入与回滚

建议先提交独立 Phase1，取消三类礼貌事件的默认增信并保留自定义覆盖。当前自动分类集合没有已验证的可靠性正向事件：此过渡会留下“暂无可靠自动 Trust 修复”的明确限制，人工编辑、Affinity 衰减或不再犯均不能冒称自动修复。固定负权重和 JOKE 不在该阶段修改。

Phase2 只修复已复现且能由可信元数据判定的受话人冲突，先入口弃权，再讨论语义上下文。纯文本引文、玩笑是否双方接受及测试性注入误判仍需标注集；本轮不凭猜测增加监控或协议。

Phase3 仅比较历史派生与离线 B-lite 摘要；缺失历史标 unknown，不能伪造证据。Phase4 复用称谓/人格边界验证，无证据不加滞回状态。Phase5 只做离线与合成验证。

本 PR 不升级 schema，不写真实数据；撤销该提交即可移除开发工具。报告目录内是一次性合成数据库，不随插件打包。运行版本仍为 0.2.1。正式发布由维护者决定。
